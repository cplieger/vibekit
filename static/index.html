      Chat retention

      Closing a chat archives it to History (toolbar icon). Days kept sets how long before it's purged. Set to 0 for no retention: closing a chat deletes it immediately and History is hidden. Enable Keep forever to never purge — History becomes a permanent archive. vibekit manages this itself; kiro-cli's own cleanup is off.

      Compaction

      When the context window fills up, kiro-cli summarizes older messages to free space. These settings control that behavior.

      Auto-compact

      Automatically summarize history when the context window is nearly full. Off means you must type /compact manually.

      Number of recent message pairs to exclude from compaction. Higher values preserve more recent context but leave less room for the model's response.

      Percentage of the context window to keep free so the model has room to respond after compaction. Higher values leave more headroom.

      Experimental features

      Optional kiro-cli capabilities. All three are on by default. Turning one off takes effect on the next conversation; running sessions keep their current configuration.

      Track file changes

      Keeps shadow-git snapshots of your workspace across the conversation so kiro-cli can roll back a failed tool call without touching your real git history. Off means a failed edit stays on disk.

      Track multi-step tasks

      Lets the agent maintain a to-do list when it breaks a big ask into steps. The list renders inline in chat as the agent ticks items off. Off means the agent works step by step without the visible tracker.

      Knowledge base search

      Indexes directories you ask it to ("add this folder to my knowledge base") for semantic search across conversations. Off removes the feature entirely — no disk usage and no knowledge tool call option.

      Show hook status in chat

      When on, kiro-cli hook executions appear as status messages in the chat transcript. Off hides them; hooks still run and enforce their rules, only the chat messages are suppressed.

      kiro-cli telemetry

      Anonymous usage telemetry sent by kiro-cli (not vibekit). Helps the Kiro team improve the CLI. Off disables all telemetry collection. This does not affect vibekit's own operation.

      Load MCP tools on demand

      When off (default), every connected MCP tool's full description is sent to the model on every prompt — the agent can call any tool immediately, but the tool list takes context-window space (~200–500 tokens per tool) on every turn. When on, kiro-cli ships only a built-in tool_search tool to the model; when the agent needs an MCP tool, it asks tool_search by intent and kiro-cli returns matches. Saves significant context tokens for users with 5+ MCP servers but adds one extra round-trip per tool the agent decides to use. Recommended only when you actually feel the context squeeze — for small MCP setups it adds latency without benefit.

      Exclude default resources from custom agents

      When on, custom agents (your own agent definitions) no longer inherit the default resources — global/workspace steering docs, skills, and AGENTS.md — so a custom agent starts from a clean context you control explicitly. The built-in Default and Plan agents are unaffected. Off (default) keeps every custom agent loading those resources automatically. Requires kiro-cli 2.10+.

      Debug logs

      Raise vibekit's server-side log level to DEBUG. Surfaces extension-notification drops, fs handler details, and other verbose diagnostics. Read the logs with docker logs vibekit. Default off.

      Tools & runtimes

      Language runtimes, LSP servers, and CLIs you can enable on demand. Disabled tools install on first use (or click Enable); the pin icon freezes a tool at its current version. Everything installs into the persistent volume, not the image.

      The Active policy below is the live permission policy kiro-cli actually enforces. The layers under it (supervised mode, shell command policy) are vibekit's own complementary controls. Defaults here apply to new conversations; the Supervised pill next to the chat prompt toggles the per-chat review gate.

      Active policy

      The native permission rules kiro-cli enforces, layered by scope. Precedence is deny > ask > allow. You can edit the user and workspace layers; edits take effect immediately, with no restart. New rules default to Ask — widen to Allow only deliberately.

      No policy rules loaded yet.

      Add a rule

      Leave match empty to apply to the whole capability. Workspace paths are workspace-relative (e.g. src/**); user paths are absolute (e.g. /home/you/project/**).

      Test a decision (why?)

      Simulate the decision for a capability + resource. This is a read-only check — it never runs the tool or raises a prompt.

      Supervised mode (default for new chats)

      A separate layer from the Active policy above. That policy decides whether the agent needs permission to run a write tool; Supervised mode decides whether the resulting file change needs your review before it's saved to disk. When on, every file change (create, edit, delete) shows up in the chat with Accept / Reject buttons and the write only lands after you approve. The Supervised pill next to the chat prompt toggles the current conversation; this setting only picks the default for new ones.

      Shell command policy

      Controls how shell commands (execute_bash, executePwsh) are handled. Read-only commands like ls, cat, git status always auto-approve in safe mode.

      Command rules

      Per-command overrides. Allow auto-approves the pattern under Safe mode (ignored in Allow all / No commands). Deny forces a prompt regardless of policy — safety net for destructive one-shots. * is a wildcard.

      No rules. Add an allow pattern to auto-approve under Safe mode, or a deny pattern to force a prompt even under Allow all.

      Agent ignore files

      Paths to gitignore-style files. The agent cannot read files matching these patterns (writes are still allowed, same as git). Good for keeping decrypted secrets (.env.dec), build artifacts, and other gitignored files out of the agent's context window. Relative entries resolve against the workspace root.

      No ignore files. Common choices: .gitignore (keeps all gitignored paths off-limits to reads), .kiroignore (dedicated vibekit-only list).

      Prepended to every conversation, on every device. Autosaves as you type. Good for always-on preferences like "respond in French" or "prefer concise answers".

      Steering docs, skills & agents

      Files in .kiro/ your agent reads as context. Steering docs load automatically (always, when matched, or when referenced); skills and agents are invoked on demand.

      No steering docs, skills or agents found.

      Knowledge bases

      Local directories indexed for semantic search. When chat.enableKnowledge is on, your agent searches these for relevant context. Indexing runs in the background; large directories take a moment.

      Knowledge is turned off. Enable it in General for the agent to use these bases during chats.

      No knowledge bases yet.

      Hooks

      Workspace automations in .kiro/hooks/. Toggle to enable or disable a hook; Run now runs a command hook and shows its output. Agent hooks run their prompt in a chat. Hook status messages in chat are controlled by the hooks.showStatus toggle in General.

      No hooks yet.
